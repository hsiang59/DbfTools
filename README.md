# DbfTool 使用說明

DbfTool 是用來**讀取、新增、刪除、查詢** DBF 資料檔（dBase、FoxPro、Visual FoxPro 等舊系統常用格式）的小工具。

## 1. 安裝與執行

- 不需要安裝：把 `DbfTool.exe`、`DbfTool.exe.config`、`settings.ini` 放在同一個資料夾，直接執行。
- 需要 **.NET Framework 4.0**（Windows XP 需 SP3；Windows 8 以上已內建較新的 .NET，可直接執行）。
- 設定檔：`settings.ini`（可用記事本編輯，說明見第 9 節）。程式會另外自動產生 `DbfTool.user.ini`（記住每個檔案選過的編碼）與 `DbfTool.log`（記錄檔）；exe 所在資料夾沒有寫入權限時，這兩個檔案會改放在 `%APPDATA%\DbfTool`。

## 2. 開啟檔案

按「選取 DBF 檔...」。程式會自動辨識格式、檢查結構，並在上方橫幅顯示**支援等級**：

| 等級 | 顏色 | 意義 |
|---|---|---|
| A 級 | 綠 | 完整支援，可讀取也可修改 |
| B 級 | 橘 | 可辨識但有疑點（例如檔案被截斷、有未知欄位型別、Memo 檔遺失）：**只能讀取**，橫幅會寫出原因 |
| C 級 | 紅 | 無法辨識或結構毀損：不開啟，橫幅與「檔案資訊與驗證」頁說明原因 |

**支援的格式**：dBase III（含 Memo）、FoxBase+／Clipper（無 Memo）、dBase IV（可讀取，Memo 為唯讀）、FoxPro 2.x、Visual FoxPro（單純資料表可寫入；含整數／貨幣／日期時間欄位或 Null 旗標者為唯讀）。

## 3. 畫面說明

- **記錄**頁：瀏覽記錄。已刪除的記錄以灰底刪除線顯示，可用「顯示已刪除」切換。Memo 欄位顯示第一行，**雙擊**可看完整內容。
- **欄位結構**頁：欄位名稱、型別、長度、小數位、位移。
- **檔案資訊與驗證**頁：版本、記錄數、Language ID、編碼判斷依據，以及所有檢查訊息。
- 狀態列：記錄數、顯示筆數、已刪除筆數、目前編碼、寫入狀態（可寫入／唯讀及原因）。

## 4. 編碼（中文亂碼時）

- 程式會依檔頭與內容自動判斷編碼（Big5、GBK、UTF-8 等），狀態列顯示判斷依據；信心不足時以橘色提醒。
- 看到亂碼就用「編碼」下拉選單切換。**切換後程式會記住這個檔案的選擇**，下次開啟直接沿用。
- 想重新自動判斷，按「自動偵測」。
- 寫入時使用目前選定的編碼。若有字元無法用該編碼表示，程式會拒絕寫入並提示，**不會悄悄改成 `?`**。

## 5. 新增、刪除

- **新增記錄**：依欄位型別提供輸入控制項（日期選擇器、邏輯下拉、多行 Memo…）。按「確定」時會完整驗證：文字過長、數值小數位超過、數值過大、編碼無法表示，都會拒絕並說明，**絕不截斷資料**。
- **複製新增**：以選取的記錄為範本新增。
- **修改記錄**：選取一筆記錄按「修改記錄」，或直接在記錄上**雙擊**（雙擊 Memo 欄位是檢視 Memo 全文）。對話框會帶出目前的值，按「確定」才寫入檔案。
  - 只會改寫**你動過的欄位**；其他欄位與刪除標記原封不動。
  - 若這筆記錄在你編輯期間被其他程式改過，程式會中止並請你按「重新整理」，不會蓋掉對方的變更。
  - 修改 Memo 時，新內容會附加在 Memo 檔尾端，舊內容仍留在檔案中（Pack 也不會縮小 Memo 檔）。
  - 無法解析的原始內容（例如數值欄位裡的 `*****`）如果沒有動它，會原樣保留。
- **刪除選取／復原刪除**：只加上或移除刪除標記，資料仍在檔案裡，可以復原。可按 Ctrl 或 Shift 多選。
- **清除已刪除**（Pack）：永久移除已刪除記錄並縮小檔案，**無法復原**（執行前會自動備份）。詳見第 7 節。

## 6. 查詢

在「記錄」頁上方：選欄位、運算子、輸入比對值，按「加入條件」；可加多個條件，選擇「全部符合 (AND)」或「任一符合 (OR)」後按「查詢」。查詢在背景執行，可取消；按「顯示全部」回到完整清單。

- 運算子：等於、不等於、包含、開頭是、大於、小於、介於、為空白、不為空白。
- 文字比對忽略大小寫與尾端空白；日期輸入 `2026-01-31`（或 `2026/01/31`、`20260131`）；Memo 欄位可搜尋完整內容。
- 空白欄位不會符合「大於、小於、介於」。

## 7. 備份、還原與 Pack

- **自動備份**：每個檔案在本次執行中**第一次修改前**備份一次，檔名為 `原檔名.dbf.日期_時間_毫秒.bak`，放在原檔同資料夾；有 Memo 檔時一併備份。預設保留最近 5 份（`BackupKeepCount`）。備份失敗時**不會修改檔案**。
- **還原**：關閉 DbfTool 與其他使用該檔案的程式，把想要的 `.bak` 複製回原檔名（Memo 檔同理）。
- **Pack 一定備份**，不受 `BackupEnabled` 設定影響。
- Pack 需要**獨佔**使用檔案：舊系統或其他視窗還開著該檔案時會被拒絕（顯示「檔案使用中」），關閉後再試。Pack 先寫到暫存檔、驗證無誤才取代原檔，失敗時原檔不變。
- **索引檔**（`.cdx`、`.idx`、`.ndx`…）：Pack 會改變記錄編號，索引必須由原系統重建，否則舊系統可能顯示錯誤資料。程式偵測到同名索引檔時會在確認視窗警告。
- Memo 檔在 Pack 後不會縮小（已刪除記錄的 Memo 內容仍留在 Memo 檔中）。
- 寫入 Memo 時一律附加在 Memo 檔尾端，不回收舊空間。

## 8. 與舊系統同時使用

- DbfTool 以「允許其他程式讀寫」的方式開啟檔案，不會擋住舊系統。
- 新增與刪除會短暫鎖定檔頭，並在寫入前重新檢查檔案結構；若檔案已被其他程式變更結構，會中止並請你按「重新整理」。
- 被其他程式鎖定時會自動重試（預設最多 20 次、每次 100 毫秒），逾時才提示「檔案目前被其他程式鎖定」。
- 其他程式新增或刪除記錄後，請按「重新整理」才會看到最新內容。
- **建議**：大量修改（尤其 Pack）時，請先讓舊系統離開該檔案。

## 9. settings.ini

```
[General]
BackupEnabled=true      ; 是否在修改前自動備份
BackupKeepCount=5       ; 每個檔案保留幾份備份
LogEnabled=true         ; 是否寫入 DbfTool.log
LockRetryCount=20       ; 被鎖定時最多嘗試次數
LockRetryDelayMs=100    ; 每次重試前等待毫秒數
```

## 10. 遇到問題

1. 先按「檔案診斷」。報告包含格式、檔頭、欄位清單、驗證結果與編碼判斷，**不含任何記錄內容與資料夾路徑**，可以複製或另存成文字檔提供給開發者。
2. 錯誤細節也會寫在 `DbfTool.log`。

| 狀況 | 可能原因與處理 |
|---|---|
| 橫幅顯示 B 級（唯讀） | 看橫幅原因：檔案被截斷、記錄數與檔案大小不符、Memo 檔遺失、未知欄位型別、版本旗標未識別 |
| 中文亂碼 | 用「編碼」下拉選單切換 Big5／GBK／UTF-8 |
| 「檔案使用中，無法 Pack」 | 其他程式（含另一個 DbfTool 視窗）還開著這個檔案 |
| 「檔案目前被其他程式鎖定」 | 稍後再試，或先讓舊系統離開該檔案 |
| 「檔案結構已被其他程式變更」 | 按「重新整理」再操作 |
| 按鈕全部停用、狀態列顯示唯讀 | 檔案不是 A 級、有「唯讀」屬性、或是不支援寫入的格式（見第 2 節） |
| 程式啟動失敗 | 確認已安裝 .NET Framework 4.0（XP 需 SP3） |

## 11. 已知限制

- Visual FoxPro 的整數、貨幣、日期時間欄位目前只能讀取，含這類欄位的檔案整檔唯讀。
- dBase IV 的 Memo 目前只能讀取。
- 一次只能修改一筆記錄；Visual FoxPro 專用型別（整數、貨幣、日期時間）與 G／P／W 類欄位不能修改。
- 不維護索引檔。
- 查詢的 AND／OR 只能二選一，不能混用。
